# Typography 版式与间距

断行只是排版的一半；另一半是断出来的内容怎样填满分给它的空间——行怎样对齐、段落怎样缩进、一行有多高、段落之间隔
多远、一个非文本盒子怎样参与一行、网格怎样约束元素，以及排版报告的内容尺寸是多少。本文解释的每个数字都会随输出
返回，其字段逐一说明见 [`output-format.cn.md`](output-format.cn.md)；本文提到的请求字段见
[`input-format.cn.md`](input-format.cn.md)，而两端对齐时一行怎样被填满见
[`line-breaking.cn.md`](line-breaking.cn.md)。

## 对齐

`TextAlignment` 有四个取值。请求上的 `Alignment` 决定整份文档用哪一个，`null` 表示交给语言决定，段落也可以声明
自己的取值：

| 取值 | 这一行做什么 | 用在哪里 |
|---|---|---|
| `Left` | 内容从它所在区间的起点开始 | 西文与未声明语言的文本；在右向左段落里，一行内容就从这里开始，因为“起点”是哪条边由方向决定 |
| `Center` | 松弛量平均分给两侧 | 标题与短行 |
| `Right` | 内容在它所在区间的末端结束 | 图注与数字列 |
| `Justify` | 一行通过移动自己的间隙填满区间 | 中日韩的默认值，以及任何这样要求的西文段落 |

- **对齐是按区间施加的。** 当文字绕开排除区、一行因此提供多于一个区间时，每个区间在自己的边界内对齐——就对齐
  而言一个区间就是一行，所以居中一个被分割的行不会把一侧的文字移到另一侧上。`Left` 与 `Justify` 让每个区间都留在
  自己的起点。
- **段落的最后一行不两端对齐。** 它在哪里结束就在哪里结束，只有它之前的行会被拉伸或挤压；提供多于一个区间的行
  即使不是最后一行，也按区间各自左对齐。
- **是哪条边由段落方向决定。** 右向左的段落从右缘填充：它的行从那里开始，混排行里的各个 run 在整行被贴到那条边
  之前就已排入视觉顺序。因此对齐讲的是行内轴，而不是屏幕意义上的左右。
- **四舍五入级别的差异不值得移动字形。** 亏空或松弛不足半个像素时，这一行留在自己的自然位置上。

## 缩进

| 字段 | 单位 | 属于谁 | 作用于什么 |
|---|---|---|---|
| `FirstLineIndent` | 字宽（em） | 请求，段落可覆盖 | 段落的第一行，除非该段落声明了自己的值 |
| `LeftIndent` | px | 段落 | 该段落的每一行 |
| `RightIndent` | px | 段落 | 该段落的每一行 |

首行缩进用**字宽**表达，因为约定就是这么写的：中文两字、日文与韩文一字、西文不留。引擎用段落的字宽把它换算成
像素——该段落第一个声明了字号的 run 的字号，没有任何声明时为 `16` px——所以“两字”对字宽等于一个字号排字是精确的，
而这正是中日韩约定所假定的情形。取零即关掉缩进，段落也可以在开启它的那个元素上声明自己的数：显式的零就是一个字
都不缩，即使它的语言要求缩两个字。

左右缩进是**绝对的像素值，不是覆盖值**：它们总是生效。它们收窄一行空间的外侧边缘，一段引用因此就是窄的；当排除区
把一行分割成多段时，左缩进从第一个区间的起点扣掉，右缩进从最后一个区间的末端扣掉——所以一行中间的排除区永远不会
给它右侧的内容加缩进。

缩进以 `LayoutLine.LineIndent` 的形式到达输出。断行时已经按它收窄了行，所以任何重新排布该行的代码都必须从同一个
地方起算，即 `LineLeft + LineIndent`；这个字段是首行缩进**加上**该行在行首不得不让出的空间——比它所注的字更宽的
注音会把行内容推进它本来会越界的那么多（见 [`annotations.cn.md`](annotations.cn.md)）。因此重新排布一行的消费者
从 `LineLeft + LineIndent` 起算，绝不要从 `LineLeft` 起算。

## 行高模型

一行和它承载的东西一样高，而它承载的并不只有文字。行盒由四部分组成，其中一部分归作者：

```
line box along the block axis
  ExtraAbove      内容在文本盒块向起始侧需要的空间
  Ascent          行上最高元素的升部
  ---------------- 行上每条基线都落在这条线上
  Descent         行上最高元素的降部
  ExtraBelow      内容在文本盒块向末端侧需要的空间
  LineSpacing     请求要求的行距
```

`LayoutLine.Height` 等于 `ExtraAbove + Ascent + Descent + ExtraBelow + LineSpacing`。`Ascent` 与 `Descent` 是行上
各元素的最大值——即字体自己的行盒，也正是行距据以度量的基准——而装不进这个盒子的一切会按侧别分开报告，于是消费者
无需知道原因就能按排版定下的尺寸画这一行：

| 什么需要这块空间 | 哪一侧 | 来自哪里 |
|---|---|---|
| 文本盒 | 两侧，即升部与降部 | 这一行量到的最高元素：字体自己的行盒，行上有更高的行内对象时则是该对象 |
| 注音带 | 块向起始侧（`ExtraAbove`） | 放在文本盒之外的注音——横排时在它上方，竖排时在列的块向起始侧。带子容纳注音的墨迹，但以注音字体自己的行度量为地板：调号会升到字体升部之上，只按行度量算出来的带子会把它存在的理由遮住 |
| 伸出的注音列 | 两侧（`ExtraAbove`、`ExtraBelow`） | 旁置注音的列超出它注的那个字的那部分，在两侧均分；留在字内不超出的列，它的空间本就从基文自己的前进量里出 |
| 下划线 | 块向末端侧（`ExtraBelow`） | 字体自带下划线（位置加粗细）超出这一行量到的降部的那部分 |
| 着重号 | 语言放它的那一侧 | 按约定，标记落在字符自己的盒子之外，所以它的空间——一个标记的偏移加上标记本身——属于这一行而不是属于字符 |

- **作者给的行距是地板，不是天花板。** 引擎会把内容要求的空间加上去，绝不会从 `LineSpacing` 里扣：带注音或带
  着重号的一行比同样的行更高，无论作者有没有为它留空间。各约定对这块空间由谁提供说法不一——有的把它留给作者的行距，
  有的要求竖排右置注音取基字一倍半的行间隙——而且都没有说作者的文档一点都没给时该怎么办，所以引擎自己预留：
  行距完全是零的文档，也不会出现两行注音叠在一起。
- **一行上的基线一起移动。** 块向起始侧的空间加在整行之上，所以行上每条基线都向内伸进 `ExtraAbove`，而下一行从整
  个盒子之下开始。因此相邻两行绝不可能重叠，无论它们各自承载了什么。
- **第一行与其它行完全一样地算。** 没有上一行可以让出空间：第一行的带子加在它自己上方、内容框之内，内容就从那里向
  下开始——这正是带注音的第一行不会紧贴内容顶端的原因。
- **`LineSpacing` 是行距，不是 CSS 意义上的行高。** 它加在文本自己的行盒（升部加降部）之上，而 clreq 与 jlreq 正是
  以这个基准度量行距；取零意味着各行站在自己的盒子上，之间什么都没有。
- **段落不能覆盖行距。** 段落拥有自己的缩进、对齐与前后间距；需要比文档更多行距的段落，只能把它写在请求里，由请求
  作用于整份文档。
- **一个空行只花行距。** 行上没有任何内容的段落分隔只前进 `LineSpacing`；没有盒子需要拼装。
- **块自成一行。** 块作为一行放置，其高度就是块自己的高度，且不携带自己的行距；自动尺寸的块怎样量出自己，与块自己的
  字段写在一起，见 [`input-format.cn.md`](input-format.cn.md)。

## 段距

| 字段 | 单位 | 属于谁 | 用来做什么 |
|---|---|---|---|
| `SpacingAfter` | px | 段落 | 该段落之后的间距 |
| `SpacingBefore` | px | 段落 | 该段落之前的间距，加在前一段落的后间距之上 |
| `ParagraphSpacing` | px | 请求 | 段落没有声明后间距时的回退值 |

两个段落之间的距离，等于前一段落的 `SpacingAfter`——段落不作声时就是请求的 `ParagraphSpacing`——加上后一段落的
`SpacingBefore`。因此段距是作为前一段落**之后**的间距施加的，而“前间距”是在它之上追加，不是替换它；什么都不声明的
段落不在自己之前留任何空间，这正是想要统一间距的文档只需在请求上说一次的原因。

段距移动的是段落，不是行：一行自己的盒子不会因此有任何变化，而且这两个字段都只从开启段落的那个元素上读，绝不从
段落内部的元素上读。

## 行内对象

非文本元素——图片、矩形、线段、调用方自己绘制的区域——是行上的原子盒子：它的范围取自自己的 `Size`，内部不会断开，
也不消耗文本字符。它的高度通过 `VerticalAlignment` 参与行盒，由该值决定这段高度怎样切成升部与降部，进而决定盒子
落在哪里：

| `VerticalAlignment` | 升部 / 降部 | 盒子落在哪里 |
|---|---|---|
| `Baseline`（默认） | 整个高度算升部 | 底部坐在文本基线上 |
| `Top` | 整个高度算升部 | 顶部对齐行盒顶部 |
| `Middle` | 一半升部、一半降部 | 以该行的文本区居中，而不是以行盒居中，所以比文字更高的对象是以它相伴的文字为中心，而不是以自己为中心 |
| `Bottom` | 整个高度算降部 | 底部对齐行盒底部，但高于它的行距 |

- **正是这次切分让对象把行撑高。** `Ascent` 与 `Descent` 取行上各元素的最大值，所以比文字更高的图片会让这一行更高，
  而它永远不会压到上一行或下一行。
- **对齐也决定输出的基线。** 对象报告的 `BaselineY` 是它盒子的块向起始边加上对齐给它的升部，于是消费者用与文字相同
  的坐标摆放对象。
- **动作根本不是盒子。** 它是零宽的标记，不占空间，而且它之后不得断开，触发点就是这样留在了它所属的文字旁边。
- **对象本身不是断点候选，但它周围的文字是**：一行可以在它之前或之后断开，除非有规则禁止
  （见 [`line-breaking.cn.md`](line-breaking.cn.md)）。

## 网格对齐

`GridStep` 默认为 `null`，即没有网格。`GridOrigin`——相对内容原点的像素距离——指明网格从哪开始，只在设置了步长时
才会被读取。

网格是一个“东西对得齐”的承诺：设置了步长之后，每个元素的行内起点都会向前移到从该行起点加上 `GridOrigin` 起算的
下一个步长倍数。它只会向前移——网格可以把元素往行里推，绝不会把它放到排版原本放的左侧——而且是逐元素施加的，这也是
排版拥有的粒度：一个簇一个元素，而一个完整的西文词就是一个簇。

网格在按区间对齐决定了行怎样填满之后、制表位生效之前运行，因为网格是全局规则，而制表位是作者指定的位置。它的目的
就是混排：中日韩与西文之间四分之一字宽的间隙，配上以一个字为步长的网格，会让一个西文词占据整数个字符格，一页文字
正是这样按列对齐的（clreq §6.2.4）。

## 内容尺寸

`LayoutResult.ContentSize` 是排版内容在内容空间里占据的盒子：最宽元素的远边，以及最后一行的块向末端，并把请求尾部的
`Padding` 算进去。内边距在四边都施加，所以这个值可以直接用作消费者的滚动区域与画布尺寸。

- 它为排版放在文本盒之外的东西而增长：悬挂的标记、注音列、被自身行内内边距撑大的背景。
- 空情形为零：没有任何行的排版没有内容尺寸可报。
- **这一对就是（行内、块向）两个延伸，再映射到内容空间。** 横排下它就是我们熟悉的宽与高；竖排下第一个分量是列推进了
  多远、第二个是最长的那一列有多长——围着列做画布尺寸的消费者从这一个值就能读到两者。

## 各语言的默认值

请求把某个受语言管辖的字段留成 `null` 时，取该语言的值；请求自己写明的值总是优先于它；而段落可以声明自己的语言，
于是一份文档可以逐段落混用下面这些取值。

| 语言 | 首行缩进 | 对齐 |
|---|---|---|
| 简体中文（`zh-Hans`） | 2 字 | `Justify` |
| 繁体中文（`zh-Hant`） | 2 字 | `Justify` |
| 日文（`ja`） | 1 字 | `Justify` |
| 韩文（`ko`） | 1 字 | `Justify` |
| 英文及各西文语言 | 无 | `Left` |
| 右向左语言（阿拉伯文、希伯来文） | 无 | `Left`，对它们而言即段落自己的起始边 |
| 未声明（`und`） | 无 | `Left` |

- **随引擎提供的语言没有一个要求行距或段距。** 两者都由请求给出，而零就是字面意思：各行站在自己的盒子上，段落之间
  除了它们自己的行什么都没有。宿主注册的语言可以同时给出这两项，那么请求把它们留成 `null` 时，就会像取缩进一样取到
  该值。
- **书写模式刻意不在表内。** 书写模式是关于文档的决策，不是语言的属性，所以声明了它的语言剖面只是在给没有选择的
  调用方一个默认值——请求一旦选择了模式，文档就按那个模式排。
- **缩进是整数个字宽**，不是像素值，对齐是一个枚举：两者都不依赖字体，这正是上面这样的表能够精确陈述它们的原因。

```csharp
using GodotNodeExtension.Component.Typography.Core.Model;

// 行盒分两侧报告，消费者据此画出整个行盒。
static float LineBox(LayoutLine line) =>
    line.ExtraAbove + line.Ascent + line.Descent + line.ExtraBelow;

// 第一个区间的内容从行的起点加上它排布时所用的缩进开始。
static float ContentStart(LayoutLine line) => line.LineLeft + line.LineIndent;
```
