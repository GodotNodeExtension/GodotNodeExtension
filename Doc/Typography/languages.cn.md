# Typography 语言

这里的「语言」是**数据，不是代码路径**。一个 `LanguageProfile` 给出某套文字约定规定的参数——行在哪里断、脚本之间留多少间隙、首行缩进与对齐的默认值、哪些显示形态替换写下来的字符、注音放在哪一侧——再由请求或段落指定一种语言来选中它们。新增一种语言就是新增一个剖面；没有任何阶段会因为「当前是哪种语言」而分支。

本文覆盖这一层：语言如何声明、随附的每种语言做什么、什么都没声明（或声明了引擎不认识的东西）时会发生什么、以及如何新增一种语言。语言进入引擎时经过的字段、以及它的决定在输出上落在哪些字段，见 [`input-format.cn.md`](input-format.cn.md) 与 [`output-format.cn.md`](output-format.cn.md)；注音的约定另有专文 [`annotations.cn.md`](annotations.cn.md)。

## 语言如何声明

语言有两个声明位置，段落是更精细的那一个。

| 位置 | 字段 | 作用范围 |
|---|---|---|
| 请求 | `TypographySettings.LanguageTag` | 本次排版的每一个段落 |
| 段落 | `ParagraphSettings.LanguageTag` | 首元素携带它的那一个段落 |

- **请求**声明整篇文档的语言。`null` 或空字符串表示「未指定」，解析到那个不做任何语言假设的剖面。几何始终归请求所有：语言从不提供自己所在的盒子，只提供盒子内部适用的规则。
- **段落**在**开启该段落**的那个元素上声明自己的语言；段落内部元素上的该字段被忽略。由于一行的缩进、禁则规则与脚本之间的间隙都是段落属性，混语言文档通常在段落边界切换：一个中文段落后面接一个英文段落，两套约定各管自己的那一段。
- **段落的语言不会推翻请求的显式覆盖值。** 请求中由语言治理的那些字段是可空的，非空值即调用方的明确选择；段落语言提供的是规则集与调用方未表态的全部默认值，而不是替换掉已经提出的要求。

```csharp
using GodotNodeExtension.Component.Typography.Core.Model;

// The document is Chinese; this one paragraph is English and is laid out by English rules.
var request = new TypographySettings { LanguageTag = "zh-Hans", MaxWidth = 320f };

var paragraph = new DrawElement { Type = DrawElement.ElementType.Text, Text = "Typography" };
paragraph.ParagraphSettings = new ParagraphSettings { LanguageTag = "en" };
```

### 未声明时的文字推断

没有声明自己语言的段落，按它**实际**是什么来读。字符本身只在一个方面说出这段文字的语言，引擎读的正是这一方面：

| 文字包含 | 推断出的语言 |
|---|---|
| 假名——平假名、片假名、半角片假名，含长音符 | `ja` |
| 谚文——音节、字母（Jamo）、兼容字母 | `ko` |
| 只有汉字 | 不推断 |

- **第一个点明脚本的字符为整段定调**，因此假名出现在第三句的段落，从第一个字起就是日文。
- **纯汉字不推断。** 简体中文与繁体中文共用一套脚本，字符本身没有任何线索可以区分；纯汉字段落保持请求声明的语言，请求也没声明时则保持「不做语言假设」的剖面。
- **其它脚本也不推断。** 字符能回答的问题只有「这段文字里有没有假名或谚文」，这足以把日文、韩文与纯汉字文字分开，却不足以认出西文段落或从右往左的段落。中文文档里的一个拉丁字母段落必须被声明，不能被猜。
- **推断的优先级高于请求。** 它回答的是这段文字实际上是什么，而中文文档里的一句日文是平常事：按文档语言排版会让它套上文档的断行、禁则、注音侧别与显示形态，而这些都属于另一段文字。推断仍然只是**默认值**——已声明的语言永远压过它。
- **已声明的语言永不被推断覆盖。** 段落一旦点名了语言，它的字符就不会再被拿去推断；推断补的是空缺，不是纠正作者。

### 优先级

一个段落的语言可以来自四个来源，由强到弱：

| 次序 | 来源 |
|---|---|
| 1 | 开启该段落的元素上的 `ParagraphSettings.LanguageTag` |
| 2 | 段落自身的文字，当它含假名或谚文时 |
| 3 | `TypographySettings.LanguageTag` |
| 4 | 完全没有语言——不做语言假设的那个剖面 |

### 标签如何匹配

- **最长前缀优先。** `zh-Hant-HK` 找到 `zh-Hant`；自身没有剖面的标签回退到已注册的最具体的祖先，剖面也可以自带一条回退链。
- **标签会被归一化**，因此 `zh_Hans` 与 `ZH-Hans` 找到同一个剖面：大小写被忽略，`_` 等同于 `-`。
- **匹配不上的标签不会被猜。** 引擎不会把不认识的语言当成中文，也不会当成任何它认识的语言：它落到不做语言假设的剖面（见《没有剖面的语言》）。

## 语言决定什么

剖面拥有的是行为，从不是几何。它能说的每一项都是一个值，而每个值都是请求可以覆盖的默认值。

| 方面 | 剖面参数 | 表现在哪里 |
|---|---|---|
| 断行机会 | `BoundaryRuleFeature` | 由哪套规则决定行可以在哪里断：Unicode 算法，或在其之上裁剪出的禁则规则 |
| 禁则 | `EnableLineProhibition`、`ProhibitionLevel`、`ProhibitionClassSetId` | 某个边界被禁止行首或行末断开，以及一行比它的宽度所允许的更早结束 |
| 中西间距 | `EnableCjkLatinSpacing`、`CjkLatinSpacingEm`、`CjkLatinSpacingMinEm`、`CjkLatinSpacingMaxEm` | 两个元素之间的自然间隙，以及两端对齐时它可以被拉伸或挤压到多少 |
| 标点挤压 | `EnablePunctuationCompression` | 一行末尾的标点最多能压到多窄 |
| 行末标点 | `LineEndPunctuation` | 结束一行的全角标点是被剪掉半字宽，还是保住自己的半字宽 |
| 行首开括号 | `HalfWidthOpeningBracketAtLineHead` | `Reason` 为 `OpeningBracketHalfWidth` 的元素 |
| 悬挂标点 | `HangingPunctuation` | 允许标点越出行末边缘时，`LayoutElement.Hanging` |
| 缩进与对齐 | `FirstLineIndent`、`Alignment`、`LineSpacing`、`ParagraphSpacing` | 首行从哪里开始，以及一行如何填满它拥有的空间 |
| 文字方向 | `Direction` | 一行从哪条边缘开始填充，以及一行内元素的出场顺序 |
| 书写模式 | `WritingMode` | 请求没有指定书写模式时用的那一种 |
| 地区字形 | `OpenTypeLanguageTag` | 字体绘制哪一套地区形态：同一个码位在中、日、韩字体里画出来并不相同 |
| 自动断词 | `HyphenationPatternsId` | 长词能否在词内断开，以及在哪里断 |
| 显示形态 | `EnableLetterformSubstitution`、`Letterforms` | 画出来的字符与写下来的不同时，`LayoutElement.DisplayText` |
| 注音 | `RubyPlacement`、`RubyOrientation` | 注音放在哪里、按哪个方向读，以及行为此预留的空间 |
| 着重号 | `EmphasisSide`、`EmphasisMarkSizeEm` | 记号落在字符的哪一侧，以及它有多大 |

## 逐语言

随附的每个剖面都声明横排：没有哪种语言要求竖排，竖排是请求的选择。下面每节说明该语言的约定贡献了什么，以及**看什么**才能看到它。

### 简体中文（`zh-Hans`）

- **断行与禁则。** 采用禁则规则集，用的是 clreq §6.1.1 的中文类集、basic 档：停顿与句末标点、闭引号、闭括号、连接号、间隔号与斜线不得出现在行首，开引号与开括号不得出现在行末。GB 档在行末加入斜线，strict 档在行首加入破折号与省略号。
- **中西间距。** 四分之一 em，可压到 1/8 em、可拉到 1/2 em（clreq §6.3.3），插在汉字与拉丁字母或数字相接的位置。
- **缩进与对齐。** 首行缩进两个字；两端对齐。
- **行末标点。** 结束一行的全角标点，在行需要空间时被剪掉尾部半 em（clreq §6.2.2.3）。不得出现在行首的标点也可以悬挂在行末边缘之外，而不必移到下一行（clreq §6.1.3）。
- **显示形态。** 无：写下来的就是画出来的。`“”` 与 `……` 本身就是简体形态，因此该剖面不做任何替换。
- **注音。** 在字符上方，沿行排列：拼音一类的读音，含声调符号。
- **着重号。** 横排时在字符下方（clreq §5.3.1），画作实心圆点。
- **看什么。** 一行比宽度所允许的更早结束，就是禁则起了作用，被拒断点上留证的原因会说明是哪条规则拒的；一行以句号收尾却正好塞进字形宽度说塞不下的位置，就是那半个 em 被剪掉了。

### 繁体中文（`zh-Hant`）

参数与简体中文相同——同样的类集、缩进、对齐、间距与行末宽度规则——只有三处不同。

- **显示形态。** 写下来的 `“”‘’` 画成角括号 `「」『』`，写下来的 `…` 在字面居中显示（clreq §5.2、§5.1.4）。替换改变的只有被塑形的字形与它占的宽度：源区间与字符类别仍然描述调用方写下的东西，元素把两种形态都报出来。
- **注音。** 注音符号在基字旁边，自成一行列，横排与竖排皆然（clreq §5.5.3.1）。空间来自基文自身的步进——每个被注音的字加半个基字号（clreq §5.5.3.2）——因此带注音与不带注音的行高相同，除非某一列比它所注的那个字更高。详见 [`annotations.cn.md`](annotations.cn.md)。
- **悬挂标点。** 仅在竖排时允许；横排时标点移到下一行，这也是引擎目前的做法。
- **看什么。** 与简体最直观的差别是角括号；另一个差别是注音的**方向**，因为在一个本来横排的行里，那一列会沿基字向下排。

### 日文（`ja`）

- **断行与禁则。** 采用 jlreq §3.1.7 与 §3.9 的日文类集：闭括号、连字符与破折号、感叹与问号类、间隔号、句号、逗号、迭字符、长音符与小假名不得出现在行首，开括号不得出现在行末。小假名与长音符，正是中文类集不禁止的那两类。
- **中西间距。** 四分之一 em，区间同为 1/8 到 1/2 em（jlreq §3.2.6）。
- **缩进与对齐。** 首行缩进一个字；两端对齐。
- **行末标点。** 结束一行的句号之后的半个 em 被保留，不可压缩（jlreq §3.1.9）；因此塞不下的行会更早断开，而不是把句号挤小。
- **显示形态。** 引号画成角括号（jlreq §3.1.1）。省略号保持写下来的形态，jlreq 让它落在基线上而不是重新居中。
- **注音。** 在字符上方，落在行与行之间（jlreq 的行間処理）。这一条带由引擎自己预留，而不是指望作者给的行距：否则带注音的两行会互相压住。即使请求没有给行距，两行注音也不会重叠。
- **着重号。** 横排时在字符上方（jlreq §3.3.9），默认画作圆点，元素明确要求时画作芝麻点。
- **看什么。** 一行本来还能多放一个字却没放，因为它以 `。` 结尾——那就是被保住的半个 em；而小假名或长音符从不开启一行，那是日本类集相比中文类集多出来的一类。

### 韩文（`ko`）

- **断行与禁则。** 采用 klreq §7.1.2 与 §7.1.3 的韩文类集：闭括号、连字符、感叹与问号类、间隔号、逗号、句号、迭字符与长音符不得出现在行首，开括号不得出现在行末。
- **中西间距。** 四分之一 em。klreq §7.3.2 指出谚文与拉丁文相混时有它自己的间距，但本引擎没有可以编码的规范取值，因此用与其它 CJK 剖面相同的四分之一 em，而不是自己编一个数字。
- **缩进与对齐。** 首行缩进一个字；两端对齐。
- **行末标点。** 没有宽度规则：韩文一开始就用更窄的字符，那是显示形态，不是行末做出的调整。
- **显示形态。** 引号用角括号，横排用窄句读：写下来的 `。` 与 `、` 画成 `.` 与 `,`（klreq §6.1.2、§6.1.3）。
- **注音。** 韩文没有声明自己的注音约定；注音按沿行排列、落在字符上方的方式排出来，因为每个剖面都必须有个答案，而这一个是引擎的默认值，不是对这门语言的断言。
- **着重号。** 侧别同样不由语言声明；引擎的默认值放在字符下方。
- **看什么。** 窄句读：在横排的韩文段落里写下 `。`，画出来的是 `.`。这是替换，所以 `Text` 仍然是写下来的那个字符。

### 西文（`en`、`en-GB`、`de`、`fr`）

- **断行。** Unicode 断行算法（UAX #14），不作裁剪：没有禁则类集、没有标点挤压、没有中西间距，脚本之间不插入任何东西，一行只在算法允许的地方断开。
- **缩进与对齐。** 没有首行缩进；左对齐。
- **断词。** 自动断词，用各语言自己的模式：美式英语、英式英语、德语（1996）与法语各自在模式允许的地方断长词，断点会预留连字符的步进，因此渲染器仍然只画它拿到的字形。中文、日文与韩文没有模式，因为它们的文字在字与字之间断开，词级断词会是它们没有的规则。请求可以关掉这一行为。
- **显示形态、注音、着重号。** 都没有：这些语言没有声明，因此不做替换，注音字段描述的是调用方要的东西而不是某种约定。
- **CJK 段落里的西文 run。** 两种脚本之间的间隙在边界上决定，而且是由 CJK 一侧说出一个值：夹在中文句子里的拉丁词会得到那四分之一 em，而按 `en` 排的拉丁文段落不会。两种情况下断行都跟随所在段落的规则集。
- **看什么。** 右边缘参差、行末出现断词连字符；以及两端对齐时被分配到词与词之间、而不是字与字之间的空间。

### 未声明（`und`）

- **它是什么。** 不做任何语言假设的剖面。它带着语言层出现之前引擎就有的参数，因为给一段没人声明过语言的文字套上某种约定，等于凭空发明一种约定。它是对历史的陈述，不是「未声明的文字就是中文」的断言。
- **断行与禁则。** 禁则规则集配引擎的历史类集——行首的闭标点、停顿与句末标点、间隔号、斜线、破折号与省略号，行末的开标点——basic 档。
- **中西间距。** 四分之一 em，且没有声明区间，因此间隙会被插入，但两端对齐时不可调整。
- **缩进与对齐。** 没有缩进；左对齐。
- **显示形态与塑形。** 都没有，也没有 OpenType 语言标签：未声明的文字塑形方式与从前完全一致。
- **注音与着重号。** 引擎的默认值：注音在字符上方、沿行排列；着重号在下方。
- **看什么。** 什么都不声明的文字，行为与语言层出现之前一样——所以想要某种约定的文档应该点出它。

### 阿拉伯语（`ar`）与希伯来语（`he`）

- **断行。** Unicode 算法，不做 CJK 裁剪：没有禁则、没有挤压、没有间距、没有断词。
- **方向。** 从右往左，而且这属于语言本身：一个段落说自己是阿拉伯语，就是在告诉排版它的文字朝哪边读。行从右边缘开始填充，混排行内各 run 按视觉顺序排出。
- **缩进与对齐。** 没有首行缩进；行对齐到段落的起始边，对从右往左的段落就是右边缘。
- **显示形态。** 唯一生效的替换是镜像：成对出现的字符（括号、引号）画成镜像字形（UAX #9 的 L4 规则）。它与语言的引号形态走同一条输出通道。
- **注音与着重号。** 这些约定没有声明；适用引擎的默认值。
- **看什么。** 起始边落在右边，以及朝与写下来相反方向指的括号。

## 没有剖面的语言

有两条路径最终都没有语言，理由不同，落点相同。

- **完全没有语言。** 请求没声明、段落没声明，文字里既没有假名也没有谚文，推断无从回答。排版按不做语言假设的剖面进行，保持引擎的历史行为，而不是套上没人要求的约定。
- **未注册的语言。** 给了一个标签——某个引擎没有随附剖面的语言——即便把子标签逐层去掉也匹配不到。引擎不会回退到某个它认识的语言，因为「文字的语言是引擎没学过的那个」恰恰是最不能猜的情况。该标签同样解析到不做语言假设的剖面，于是这段文字以同样的、未经裁剪的行为排出来。
- **这两种都不是错误。** 文字照样排版、照样绘制；它没有得到的，是一件它从未点名的约定。补上下面这个剖面，就能改变这一点。

## 新增一种语言

新增一种语言就是新增一个剖面——一个值，不是一条代码路径——并把它注册到查询剖面的地方。

```csharp
using GodotNodeExtension.Component.Typography.Core;
using GodotNodeExtension.Component.Typography.Core.Model;
using GodotNodeExtension.Component.Typography.Languages;

// A profile names its tag, its fallback chain, the parameters its convention prescribes, and why it prescribes them.
var turkish = new LanguageProfile(
    "tr",
    ["tr-TR"],
    new TypographyParameters
    {
        BoundaryRuleFeature = TypographyFeatureRegistry.UnicodeBoundaryRuleId,
        EnableLineProhibition = false,
        EnableCjkLatinSpacing = false,
        EnablePunctuationCompression = false,
        FirstLineIndent = 0,
        Alignment = TextAlignment.Left,
        OpenTypeLanguageTag = "TRK",
    },
    "Turkish: Western line breaking, no CJK tailoring");

LanguageProfileRegistry.Shared.Register(turkish);   // checked here; it throws when the profile cannot be laid out
```

注册期就是检查语言包的地方，坏掉的剖面会大声失败，而不是悄悄用回退规则把文字排出来。出现下列情况时剖面会被拒绝：

- **它点名的断行规则没有注册。** 引擎的两套规则——Unicode 算法与在其之上的禁则规则——互相声明冲突，因此一个剖面只能点名其中一套；而没人注册过的名字是问题，不是静默的回退。
- **它的禁则类集没有注册。** 引擎找不到的类集意味着「完全不设禁则」，与点名它的剖面想要的恰好相反。随附的类集是中文、日文、韩文三套约定加上引擎的历史类集；自有类集的宿主可以注册自己的类集并点名其 id。
- **它的书写模式是引擎排不出来的。** 横排与从右往左的竖排可以接受；其它模式在注册期就被拒，因为阶段实现不了的模式，回来时会是自称竖排的横排文字。
- **它同时要求「行上方预留注音带」与「注音沿自身列向下排」。** 带的深度等于注音的高度，而列沿基字延伸、需要旁边的空间；同时要求两者的剖面描述的是一种不可能存在的排版。

当一种语言需要的是**规则**而不是值时——比如词典分词——宿主实现断行规则接口，用自己的 id 注册，再让剖面点名那个 id。断行器不需要任何改动。这就是这一层的验收判据：**新增一种语言不得要求改动框架**。
